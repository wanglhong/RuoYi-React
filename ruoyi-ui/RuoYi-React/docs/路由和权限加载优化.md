# 路由和权限加载优化

## 问题描述

1. **getInfo接口被调用两次**
   - React的StrictMode在开发模式下会双重调用useEffect
   - 可能导致重复请求

2. **getRouters接口没有被调用**
   - 缺少permission store
   - 缺少动态路由加载逻辑

## 解决方案

### 1. 防止重复调用getInfo

#### 方法1: 使用ref标记

```typescript
// src/components/AuthGuard/index.tsx
const fetchingRef = useRef(false)

useEffect(() => {
  const initAuth = async () => {
    // 如果已经在获取，直接返回
    if (fetchingRef.current) {
      return
    }
    
    if (!fetchingRef.current) {
      fetchingRef.current = true
      try {
        await getUserInfo()
      } finally {
        fetchingRef.current = false
      }
    }
  }
  
  initAuth()
}, [deps])
```

#### 方法2: 移除StrictMode（生产环境自动移除）

```typescript
// src/main.tsx
const root = ReactDOM.createRoot(document.getElementById('root')!)

if (import.meta.env.PROD) {
  root.render(<App />)
} else {
  root.render(
    <React.StrictMode>
      <App />
    </React.StrictMode>
  )
}
```

### 2. 实现getRouters调用

#### 创建Permission Store

```typescript
// src/store/modules/permission.ts
import { create } from 'zustand'
import { getRouters } from '@/api/user'

interface PermissionState {
  routes: any[]
  sidebarRouters: any[]
  isLoaded: boolean
}

interface PermissionActions {
  generateRoutes: () => Promise<any[]>
  setSidebarRouters: (routes: any[]) => void
  resetPermission: () => void
}

export const usePermissionStore = create<PermissionState & PermissionActions>()(
  (set, get) => ({
    routes: [],
    sidebarRouters: [],
    isLoaded: false,

    generateRoutes: async () => {
      try {
        const res = await getRouters()
        
        if (res.code !== 200) {
          throw new Error(res.msg || '获取路由失败')
        }

        const routerData = res.data || []
        const routes = filterAsyncRouter(routerData)
        
        set({
          routes,
          sidebarRouters: routes,
          isLoaded: true
        })
        
        return routes
      } catch (error) {
        console.error('获取路由失败:', error)
        set({ isLoaded: true })
        return []
      }
    },

    setSidebarRouters: (routes) => {
      set({ sidebarRouters: routes })
    },

    resetPermission: () => {
      set({
        routes: [],
        sidebarRouters: [],
        isLoaded: false
      })
    }
  })
)
```

#### 在AuthGuard中调用

```typescript
// src/components/AuthGuard/index.tsx
const { generateRoutes, isLoaded } = usePermissionStore()

// 有token但没有用户信息
if (token && roles.length === 0) {
  if (!fetchingRef.current) {
    fetchingRef.current = true
    setLoading(true)
    try {
      // 获取用户信息
      await getUserInfo()
      console.log('用户信息获取成功')
      
      // 获取路由信息
      await generateRoutes()
      console.log('路由信息获取成功')
    } finally {
      setLoading(false)
      setInitialized(true)
      fetchingRef.current = false
      NProgress.done()
    }
  }
}
// 有用户信息但没有路由信息
else if (token && roles.length > 0 && !isLoaded) {
  if (!fetchingRef.current) {
    fetchingRef.current = true
    setLoading(true)
    try {
      await generateRoutes()
      console.log('路由信息获取成功')
    } finally {
      setLoading(false)
      setInitialized(true)
      fetchingRef.current = false
      NProgress.done()
    }
  }
}
```

## 执行流程

### 完整流程

```
用户登录成功
    ↓
跳转到首页
    ↓
AuthGuard检查权限
    ↓
获取用户信息 (getInfo)
    ↓
获取路由信息 (getRouters)
    ↓
渲染页面
```

### 详细步骤

1. **登录成功**
   - 保存token到Cookie
   - 跳转到首页

2. **AuthGuard初始化**
   - 检查token是否存在
   - 检查用户信息是否已加载
   - 检查路由信息是否已加载

3. **获取用户信息**
   - 调用getInfo API
   - 更新用户状态（roles、permissions等）

4. **获取路由信息**
   - 调用getRouters API
   - 存储路由数据
   - 后续用于动态路由加载

5. **渲染页面**
   - 显示首页内容
   - 显示侧边栏菜单

## 防止重复调用机制

### 使用ref标记

```typescript
const fetchingRef = useRef(false)

if (fetchingRef.current) {
  return  // 如果正在获取，直接返回
}

fetchingRef.current = true
try {
  await getData()
} finally {
  fetchingRef.current = false
}
```

### 好处

- ✅ 防止StrictMode导致的重复调用
- ✅ 防止快速点击导致的重复调用
- ✅ 简单高效，不需要额外状态管理

## getRouters API格式

### 请求

```
GET /getRouters
```

### 返回格式

```json
{
    "msg": "操作成功",
    "code": 200,
    "data": [
        {
            "name": "System",
            "path": "/system",
            "component": "Layout",
            "meta": {
                "title": "系统管理",
                "icon": "system"
            },
            "children": [
                {
                    "name": "User",
                    "path": "user",
                    "component": "system/user/index",
                    "meta": {
                        "title": "用户管理",
                        "icon": "user"
                    }
                }
            ]
        }
    ]
}
```

### 字段说明

- `code`: 状态码，200表示成功
- `msg`: 提示信息
- `data`: 路由数组
  - `name`: 路由名称
  - `path`: 路由路径
  - `component`: 组件路径
  - `meta`: 元数据（标题、图标等）
  - `children`: 子路由

## 注意事项

1. **开发环境**: StrictMode会导致双重渲染，这是正常行为
2. **生产环境**: StrictMode会自动移除，不会有双重调用
3. **ref标记**: 确保在finally中重置，避免死锁
4. **错误处理**: 添加适当的错误处理，避免阻塞页面渲染
